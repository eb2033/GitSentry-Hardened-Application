# checklists

Sign-off checklists for build phases. One file per phase, named after the phase.

## Rules

- Use `- [ ]` and `- [x]` items. Tick an item only when the user confirms it was checked, never on assumption.
- Each file opens with the work packages it covers, a link to the part of `../PLAN.md` it comes from, and a last-updated date.
- Mark items that may wait with *(can wait until <month>)* rather than deleting them.
- Keep checks verifiable: name the command, the denied action or the file that proves the item.
- When the plan changes, update the affected checklist in the same edit.
